# LEDCAST

Видео по Wi‑Fi на светодиодные бегущие строки из модулей HUB75.

LEDCAST превращает дешёвый контроллер **Huidu HD‑WF2** (ESP32‑S3) в сетевой
видеоприёмник, а компьютер — в пульт: приложение берёт картинку из любого
**NDI‑источника** (Resolume, OBS, vMix, TouchDesigner…), раскладывает её по
строкам и отправляет каждой строке её кусок кадра без потерь цвета.

```
 Resolume / OBS ──NDI──▶ LEDCAST Console ──UDP Frame v6──▶ HD‑WF2 ──HUB75──▶ панели
   (компьютер)            (macOS / Windows)   ◀─обратная связь─   (ESP32‑S3)
```

## Зачем

Штатная прошивка Huidu рассчитана на заранее загруженные ролики и тексты с
3 битами цвета. Для живого шоу нужно другое: строки должны показывать то, что
сейчас идёт с видеосервера, синхронно, с нормальной глубиной цвета и без
отдельного «LED‑процессора» за тысячи долларов. LEDCAST закрывает эту задачу
на плате стоимостью в несколько долларов:

- **до 8 бит на канал** с гамма‑коррекцией CIE 1931 и упорядоченным дизерингом;
- **до 120 кадров/с** на строку (30, 60 или 120), несколько строк
  параллельно, каждая — своим потоком;
- **синхронно на всех строках**: строки сверяют часы с Console и меняют кадр в
  один и тот же момент, без отдельного синхронизатора; общая задержка показа
  (25–100 мс) гасит паузы Wi‑Fi;
- **без потерь цвета**: RGB888 едет до контроллера как есть (Raw или LZ4);
- **без «рваных» кадров**: кадр выводится только целиком, после проверки CRC32,
  а одна потерянная UDP‑датаграмма восстанавливается по чётности;
- **автономный режим**: строка может сама показывать статичный или бегущий текст
  без компьютера;
- **без кнопок на площадке**: три включения питания подряд, каждое короче 5 с,
  поднимают собственную точку доступа строки, даже если её Wi‑Fi рядом, и
  запускают встроенное шоу (раздел «На площадке без своего Wi‑Fi» ниже);
- **настройка из браузера**: модули, порядок и поворот панелей, скан, драйверы,
  Wi‑Fi, тест‑паттерны, обновление прошивки по воздуху с
  ходом загрузки прямо на строке;
- **живучесть**: откат неудачной прошивки, безопасный режим после трёх сбоев
  подряд, запись последней паники со стеком вызовов;
- **Console**: превью каждой строки, кадрирование, поворот и отражение, яркость
  и автономный показ из карточки, веб‑интерфейс строки в отдельном окне.

## Железо

- Контроллер **Huidu HD‑WF2 ревизии V7.x** (ESP32‑S3, 8 МБ flash, без PSRAM).
  Ревизии V6 и старше построены не на ESP32 и не подходят.
- Модули HUB75/HUB75E: от 1 до 24 в одной цепочке, высота до 64 точек,
  сканы 1/2…1/32, включая P10 32×16 1/4 со сложными раскладками.
- Блок питания 5 В на клеммник платы (от USB плата не питается).

Подробности — распиновка, состав платы, память, грабли — в
[docs/hardware.md](docs/hardware.md).

## Быстрый старт

### 1. Прошить контроллер

**Из браузера.** Откройте страницу установки (GitHub Pages репозитория,
ссылка — в описании последнего релиза) в Chrome или Edge, переведите плату в
режим загрузки — замкнуть `GPIO0` на `GND`, подать питание 5 В, разомкнуть —
подключите USB‑A платы к компьютеру и нажмите «Установить LEDCAST».

**Вручную.** Скачайте `ledcast-firmware-<версия>-first-install.bin` со страницы
[Releases](../../releases/latest) и запишите его с адреса 0:

```sh
python -m esptool --chip esp32s3 write_flash 0x0 ledcast-firmware-0.1.0-first-install.bin
```

Полный образ (и установка из браузера) стирает настройки — сеть, модули, всё.
Дальнейшие обновления ставятся из веб‑интерфейса контроллера (вкладка
«Система») файлом `ledcast-firmware-<версия>-ota.bin`: он настройки не трогает.

### 2. Подключить к сети

После первой загрузки контроллер поднимает точку доступа `LEDCAST-XXXX`
(пароль `88888888`). Подключитесь к ней — страница настройки откроется сама,
или зайдите на `http://192.168.4.1`. Пароль веб‑интерфейса тот же, `88888888`;
смените его на вкладке «Система». Во вкладке «Сеть» подключите контроллер к
Wi‑Fi площадки, во вкладке «Оборудование» задайте модули и их порядок.

Дальше контроллер доступен по адресу `http://ledcast-xxxx.local` (те же четыре
знака, что в имени точки доступа) или по IP из роутера.

### 3. Запустить LEDCAST Console

Скачайте со страницы [Releases](../../releases/latest)
`LEDCAST-Console-<версия>-macOS-universal.zip` (Apple Silicon и Intel) или
`LEDCAST-Console-<версия>-Windows-x64.zip`: внутри готовое `LEDCAST Console.app`
и `LEDCAST-Console.exe`. На macOS установите
[NDI Runtime](https://ndi.video/tools/); в Windows‑архив он уже вложен.

Строки в той же сети Console находит сама через mDNS. Новая строка
показывается как «Не подключена»: нажмите «Подключить» и один раз введите
пароль её веб‑интерфейса — дальше Console входит своим ключом. Назначьте
каждой строке NDI‑источник, кадрирование и поворот, нажмите «Старт».

Задержка в шапке Console — время от кадра источника до его показа, одно на все
строки. Чем она больше, тем более долгие паузы Wi‑Fi строки переживают без
пропусков; по умолчанию максимальная, 100 мс. Строка держит столько кадров, сколько
помещается в её память: если какой‑то строке не хватает, Console опускает
задержку для всех и говорит, из‑за какой строки.

### На площадке без своего Wi‑Fi

Строка, которая знает Wi‑Fi площадки, подключается к нему сама — и тогда без
доступа к этой сети до неё не добраться. Кнопок на корпусе нет, поэтому
автономный запуск включается питанием:

1. Включите строку. Если показывать ей нечего, на экране три квадрата, первый
   закрашен, полоса под ними тает. Выключите её раньше чем через 5 секунд —
   дождитесь, пока экран погаснет.
2. Включите и выключите так же ещё раз: закрашено два квадрата.
3. Включите в третий раз. Строка поднимает точку доступа `LEDCAST-XXXX` и
   запускает встроенное шоу; если текста в шоу нет — горят три зелёных
   квадрата. Подключитесь к точке и настройте строку, как в шаге 2.

Если строка уже показывает шоу или видео, квадратов нет, но включения
считаются так же. Строка, проработавшая дольше 5 секунд, начинает счёт заново.
Следующее обычное включение возвращает её в сохранённую сеть; включённое шоу
остаётся включённым, пока его не выключат в веб‑интерфейсе.

## Сборка из исходников

### Прошивка

Нужен [ESP‑IDF 5.5](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/get-started/).

```sh
. $IDF_PATH/export.sh
cd firmware
idf.py build
idf.py -p /dev/cu.usbmodem101 flash monitor
```

Веб‑интерфейс (React + prime-ui-kit) собирается автоматически вместе с прошивкой
(`firmware/web/build.py` → Vite → один gzip‑файл внутри образа). Нужен Node.js и
один раз `npm ci` в корне репозитория. Без железа интерфейс открывается командой
`npm run dev -w firmware/web` с моком контроллера (пароль `ledcast1`);
`LEDCAST_DEVICE=http://<ip> npm run dev -w firmware/web` — с настоящим устройством.

### Тесты прошивки на компьютере

Платформонезависимая логика — модель конфигурации, разбор и сборка кадров,
раскладка модулей, расчёт памяти DMA, BCM, сеть — проверяется без платы:

```sh
cmake -S firmware/test -B build-host
cmake --build build-host -j
ctest --test-dir build-host

npm test                                  # логика обоих веб-интерфейсов (node --test)
```

### LEDCAST Console

Нужен Rust 1.82+. Сборка и упаковка — в [desktop/README.md](desktop/README.md).

```sh
cd desktop
cargo run --release
```

## Релизы

Готовые файлы не хранятся в git — так принято: бинарник в истории остаётся
навсегда и раздувает каждый клон, а релиз привязан к тегу и проверяем.

**Локально** каждая часть собирает установочные файлы в свой `dist/`
(игнорируется git):

```sh
. $IDF_PATH/export.sh && firmware/package.sh   # → firmware/dist/
desktop/package-macos.sh                        # → desktop/dist/ (на Mac)
desktop\package-windows.ps1                     # → desktop\dist\ (в Windows)
```

**Публикация** — тегом. Версия задаётся в `firmware/CMakeLists.txt`,
`desktop/Cargo.toml` и `desktop/tauri.conf.json`; `scripts/check-version.sh`
проверяет, что они совпадают.

```sh
scripts/check-version.sh
git tag v0.1.0 && git push origin v0.1.0
```

Workflow [Release](.github/workflows/release.yml) теми же скриптами собирает
прошивку, macOS‑ и Windows‑приложение и публикует релиз:

| Файл | Что внутри |
|---|---|
| `LEDCAST-Console-<версия>-macOS-universal.zip` | `LEDCAST Console.app`, Apple Silicon + Intel |
| `LEDCAST-Console-<версия>-Windows-x64.zip` | `LEDCAST-Console.exe`, NDI runtime, README |
| `ledcast-firmware-<версия>-first-install.bin` | полный образ прошивки с адреса 0x0 |
| `ledcast-firmware-<версия>-ota.bin` | обновление прошивки из веб‑интерфейса |
| `SHA256SUMS` | контрольные суммы всех файлов |

`.app` — это папка, поэтому для скачивания она упакована в zip; `.exe` лежит в
zip вместе с NDI‑библиотекой, без которой не видно источников.

У публичного репозитория workflow ещё подписывает происхождение файлов (build
provenance) и обновляет страницу установки прошивки на GitHub Pages — на
бесплатном плане GitHub у приватного репозитория этих функций нет. Проверить
скачанный файл:

```sh
gh attestation verify LEDCAST-Console-0.1.0-macOS-universal.zip -R <владелец>/ledcast
```

## Структура репозитория

```
firmware/
  main/              точка входа: порядок запуска и применение настроек
  components/
    deviceconfig/    модель настроек, проверка допустимости, хранение в NVS
    linear/          линейная модель строки: порядок, повороты, отражения модулей
    stream/          приёмник LEDCAST Frame v6: сборка, FEC, декодирование, часы, плейаут
    display/         вывод на HUB75: пересборка драйвера, яркость, BCM
    hub75-panel/     драйвер HUB75 на GDMA (доработанный ESP32-HUB75-MatrixPanel-DMA)
    dmapool/         бюджет DMA-памяти под буферы вывода
    colour/          гамма и дизеринг
    show/            автономный показ текста
    netconfig/       Wi-Fi STA/AP, captive portal, mDNS
    webui/           HTTP API и веб-интерфейс
    health/          безопасный режим, подтверждение OTA, тройное включение, паника, кнопка, светодиод
    framestats/      телеметрия кадров
  web/               веб-интерфейс контроллера: React + prime-ui-kit, Vite, мок устройства в dev/
  installer/         страница установки прошивки из браузера (ESP Web Tools)
  package.sh         сборка установочных файлов в firmware/dist/
  test/              host-тесты (CMake/CTest)
desktop/
  src/               ядро приложения: NDI, маппинг, кодер и отправка Frame v6, часы
  web/               интерфейс: React + prime-ui-kit в Tauri WebView, мок бэкенда в src/dev/
  package/           файлы упаковки macOS/Windows
  package-*.sh/.ps1  сборка установочных файлов в desktop/dist/
scripts/             проверка версий для релиза
package.json         npm workspaces обоих веб-интерфейсов (typecheck, тесты, сборка)
.github/             CI, релиз, Dependabot
docs/                документация
```
